# マージ同期（試験的）

既定の同期は置き換えで、2 台の PC で並行して変更が生まれると、後から Push した側だけが残る。マージ同期を有効にすると、そのツールの DB について次の 2 つの場面で、上書きの代わりに「同期先の最新に、手元にしか無い変更を足す」処理を行い、結果をそのまま Push する。VRCX と VRC Friend Connect で別々に有効にする。

- Pull で、手元に未 Push の変更が見つかったとき。起動時の自動 Pull、手動の Pull、競合時の「先に Pull」、別の PC の更新の通知からの Pull のどれも同じ（非常用の強制 Pull を除く）
- Push が「リモートの方が新しい」ことで競合したとき（強制 Push を除く）

マージ同期が無効のときは、Pull は手元の変更を見つけると上書きせずに見送る。GUI では強制 Pull で上書きするかを尋ね、CLI は終了コード 3 で止まる。手元の変更を確かめられない場合（前回の同期時点の要約が無いなど）は、どちらの設定でも従来どおり上書きする。

## ファイルごとの扱い

行単位で合わせるのは各ツールの DB である。DB 以外のファイルは行単位で合わせられないので、マージを始めた PC の手元のものを Push する。例外は Friend Connect のサムネイルのフォルダで、DB の写真の一覧 (`Photo`) と対応しているので、フォルダの中身を和集合にする。

| ツール | ファイル | マージ同期での扱い |
| --- | --- | --- |
| VRCX | `VRCX.sqlite3` | 下の「VRCX」の表の規則でマージする |
| VRCX | `VRCX.json` | マージせず、手元のものを Push する |
| VRC Friend Connect | `db\db_1.1.sqlite` | 下の「VRC Friend Connect」の表の規則でマージする |
| VRC Friend Connect | `thumbnails\` | 同期先にあって手元に無いファイルのうち、前回の同期の後に同期先で増えたものを手元へ取り出してから、手元のものを Push する (下記) |
| VRC Friend Connect | `config.json`、旧版の `db\db.sqlite` | マージせず、手元のものを Push する |

サムネイルの和集合は、写真の一覧の 3-way と同じ向きにそろえる。マージは、同期先の一覧にあって手元に無いファイルのうち、前回の同期時点の一覧 (要約と一緒に残す) に無いものだけを取り出す。前回の同期時点にあって今は手元に無いファイルは、手元で消したものなので戻さない。続く Push が手元の一覧を送るので、同期先の一覧も和集合になり、手元で消したものは一覧から落ちる。同期先で消されたファイルだけは手元に残って送り直される (写真の行は 3-way で消えるので、行の無いサムネイルとして残る)。前回の同期時点の一覧が無い場合 (この版より前のツールが取った要約や、DB だけから取り直した要約) は、手元で消したかどうかを見分けられないので、同期先にあって手元に無いファイルをすべて取り出す。取り出せなければ、DB を置き換える前に中止する。

## 前回の同期時点との比べ方

表の「種類」は次の 3 つである。

| 種類 | 手元にしか無い変更の見つけ方 | 足し方 |
| --- | --- | --- |
| 追加専用の履歴 | 前回の同期の後に手元で増えた行 | 同期先に無い行を手元から足す (和集合) |
| 編集されるデータ | キーごとに、前回の同期時点の内容と比べて変わったもの | 手元だけで変えた (足した・書き換えた・消した) キーは手元の内容に、同期先だけで変えたキーは同期先の内容にそろえる |
| 対象外 | 比べない | 同期先の内容がそのまま残る |

編集されるデータで、同じキーを両方の PC で別々に変えていた場合の扱いは、表の「両方で変えていたとき」の列に書いた。片方で消し、もう片方で編集していた場合は、どのテーブルでも編集した側の内容を残す (書いた内容が失われる方が取り返しがつかないため)。

## VRCX

| データ | テーブル | 種類 | 両方で変えていたとき |
| --- | --- | --- | --- |
| VRChat のログの履歴 | `gamelog_location`、`gamelog_join_leave`、`gamelog_portal_spawn`、`gamelog_video_play`、`gamelog_resource_load`、`gamelog_event`、`gamelog_external` | 追加専用の履歴 | 後から書き込まれる滞在時間 (`gamelog_location.time`) は大きい方の値を残す |
| フレンドの動きの履歴 | `feed_gps`、`feed_status`、`feed_bio`、`feed_avatar`、`feed_online_offline`、`friend_log_history` | 追加専用の履歴 | (書き換わらない) |
| 通知 (旧形式) | `notifications` | 追加専用の履歴 | 期限切れ (`expired`) は大きい方の値を残す |
| 通知 (新形式) | `notifications_v2` | 編集されるデータ | 編集時刻 (`updated_at`) の新しい方を残す。ただし既読 (`seen`) と期限切れ (`expires_at`) は、一方で付けていればどちらの行を残しても残す |
| 着用したアバターの履歴 | `avatar_history` | 編集されるデータ | 最後に着けた時刻 (`created_at`) の新しい方を残す。累計の着用時間 (`time`) は、前回の同期時点の値に双方で延びた分を足す |
| ユーザー・ワールド・アバターのメモ | `memos`、`world_memos`、`avatar_memos` | 編集されるデータ | 編集時刻 (`edited_at`) の新しい方を残す |
| VRChat 側に保存するユーザーのメモの写し | `notes` | 編集されるデータ | VRChat が付けた時刻 (`created_at`) の新しい方を残す |
| アバターのタグ | `avatar_tags` | 編集されるデータ | 同期先の内容を残す |
| お気に入り (ワールド・アバター・フレンド・プリント) | `favorite_world`、`favorite_avatar`、`favorite_friend`、`favorite_print` | 編集されるデータ (行の有無だけ) | (行の有無だけなので食い違わない) |
| キャッシュや VRChat 側の写し | `cache_*`、`activity_*_v2`、`mutual_graph_*` など、上に無いすべてのテーブル | 対象外 | 同期先の内容が残る |

`feed_*`、`friend_log_history`、`notifications`、`notifications_v2`、`avatar_history`、`notes` は、実際にはユーザーごとに接頭辞の付いた名前 (`usr0123abcd_feed_gps` など) を持つ。

手元の DB はマージ前にバックアップへ退避する。次のような安全に合わせられない状態では、マージを中止して従来の動作に戻る。

- 両方の DB の列が食い違う
- 前回の同期時点の要約が古い形式か、列が減っている
- 前回の同期の後に、手元で履歴の行を消した
- 同期先で消された履歴の行の滞在時間を、手元で書き換えた可能性がある
- 前回の同期の後に増えた列の値が、両方で違う
- 手元で足す古い履歴より新しい行が同期先に多すぎて、id を振り直した記録を残せない
- 前回の同期時点にあったテーブルが、片方で消されてもう片方で変わっている
- 前回の Push が同期先に反映されたか分からないまま、同期先が進んでいる
- 前回の Push の後に、別の PC が強制 Push で上書きした
- マージの間に VRCX が DB を書き換えた

| --- | --- | --- | --- | --- |

| 写真のお気に入り | `PhotoFavorite` (撮影時刻) | 編集されるデータ (行の有無だけ) | 足す・消す | (行の有無だけなので食い違わない) |

| Friend Connect の稼働区間 | `ScanRuntime` (開始時刻) | 追加専用の履歴 | 同期先に無い行を足す。動作中に伸びる終了時刻 (`endAt`) と秒数 (`seconds`) は大きい方の値を残す | — |
| ステータスの履歴 | `UserStatus` (ユーザーの ID と開始時刻) | 追加専用の履歴 | 同期先の id に付け替えて足す。ユーザーが同期先に無ければ写す。相手の PC が動いていた期間の行は足さない (下記)。滞在中に伸びる `endAt` と `seconds` は大きい方の値を残す | — |

| ワールド訪問の集計 | `UserWorldVisit` (ユーザーの ID とワールドの ID) | 集計 | 同上。回数と秒数を合成した行は、平均滞在時間 (`stayAvg`) を秒数 ÷ 回数 (切り捨て) で求め直す。Friend Connect が保持期間を過ぎて消した行は、手元がその後も数えていなければ戻さない | 列ごとに合成する (下記) |
| ユーザーの分析結果 | `UserAnalytics` (ユーザーの ID) | 集計 | 同期先に無いユーザーの行だけ写す。手元で消えていても同期先の行は残す | 同期先の内容を残す |
| VRChat 側のお気に入りの写しなど | 上に無いすべてのテーブル | 対象外 | — | 同期先の内容が残る |

表の「書き方」の背景は次のとおり。

- Friend Connect の DB では全テーブルの id が PC ごとに別の値を取るので、行は VRChat の ID やタグ名などの自然キーで突き合わせ、別のテーブルを id で指す列は同期先の id に付け替える。指す先のユーザーやワールドが同期先に無ければ、その行も手元から写す (最後に見た履歴を指す列は Friend Connect が埋め直すので空にする)。
- メモやタグの定義のように他の行から参照される行は、消して入れ直すと参照している行が連鎖して消えるので、行はそのまま列だけを書き換える。
- 手元で消したタグやグループは、参照する側のテーブルを合わせた後に消す。前回の同期の後に同期先だけでそのタグやグループを使う行が足されていれば、消さずに残す。
- 両方で別々に編集されていた場合に同期先の内容を残すのは、Friend Connect の `updatedAt` が起動しているだけで書き換わり、編集時刻として使えないためである。手元の内容はバックアップに残る。
- 稼働区間 (`ScanRuntime`) と履歴 (`UserStatus`、`UserAvatar`、`LocationMaster`、`Location`、`Video`) は、Friend Connect がこれらの行を消す操作を持たない。そのため、規則に加える前の版のツールが取った要約に祖先が無くても、中止せずに全行を突き合わせて和集合を取る (他のテーブルは祖先が無く内容が違えば中止する)。写真の一覧 (`Photo`) も祖先が無くても中止しないが、祖先の無い 2-way では手元で消した写真は伝わらず、両方にあって内容が違う写真は同期先の内容を残す。稼働区間は Friend Connect の起動 1 回が 1 行で、動作中は毎分 `endAt` が伸びる。
- インスタンスのマスタ (`LocationMaster`) の id は、他のテーブルのような連番ではなく、Friend Connect が入力 (日付、ワールド、インスタンス番号) から決めるハッシュ値で、32 bit の全域に散り、新しい行の id が既存の行より小さいこともある。そのため「前回の同期の後に増えた行」を rowid の範囲では取れず、全行を id で突き合わせる。id が 2 台の PC で同じ値を取ること (入力から決まり、PC 固有の値を含まないこと) は、Friend Connect のスキーマの注記から立てた前提であり、2 台の実データで同じインスタンスの行を比べて確かめてはいない。前提が崩れていると、同じ id が別のインスタンスを指す (手元の滞在が同期先の別のインスタンスに結び付く) か、同じインスタンスが別の id で二重になる (滞在の一覧が 2 つに分かれる) かのどちらかが起きる。前者は、同じ id の行でインスタンスの文字列 (`location`) が違えば中止することで防ぐ。後者は検出できないが、履歴が失われることはない。2 台目の PC に Friend Connect のデータがそろったら、同じ日に同じインスタンスにいた行の id を比べて前提を確かめる。
- 滞在を指す列 (`Video.locationId`、`Photo.locationId`、`LocationNote.locationId`) は、滞在をユーザーの VRChat の ID と開始時刻で見分けて付け替える。相手の PC の稼働中に手元が記録した滞在は足さないので、その間の動画や写真が指す滞在は同期先に無い。その場合は、その時刻を含む同じユーザーの滞在 (相手が記録したもので、開始時刻がポーリングの分だけ違う) を代わりに指す。それも無ければ、動画は滞在を写し (NOT NULL のため)、写真は対応を空にする。
- 2 台の PC で同時に Friend Connect を動かしていた期間は、両方が同じ出来事 (フレンドのステータスやアバターの変化) を記録していて、記録した時刻 (`startAt`) がポーリングの分だけずれるので、キーの一致では重複を除けない。そこで、同期先の稼働区間のうち手元が知らない部分 (手元に無い区間の全体と、手元にもあるが同期先の終了時刻の方が遅い区間のその後の部分) を「相手が動いていた期間」とみなし、手元の履歴のうち `startAt` がその期間に入る行は足さない。相手が動いていなかった時間の記録だけを足すので、曖昧な突き合わせ無しで重複を避けられる。相手の起動や停止をまたぐ出来事 (相手が止まっている間に始まり起動後も続いた、または相手の稼働中に始まり停止後も続いた) は、停止後の記録を失わないよう足すので、期間の中で重なる 2 行が残るが、頻度は低い。足さなかった行数はマージの結果に出る。
- 手元から写したユーザーの「最後に見た履歴」を指す 3 列 (`lastUserAvatarId` など) は空のまま写し、Friend Connect に埋め直させる。履歴を足した後にこの列が古い行を指したままになるかは、実機で確かめる。
- 写真の一覧は、Friend Connect が写真フォルダを読み直すときに行を消して入れ直す (id が安定しない) ので、追加専用ではなく撮影時刻をキーにした編集されるデータとして扱う。比べるのはサムネイルの列だけなので、入れ直しは変更と見なさない。
- 同席とワールド訪問の集計 (`UserConnection`、`UserWorldVisit`) は、Friend Connect が履歴を 1 行ずつ数えて既存の行に足していく増分の集計で、行を消しても作り直されない (実機で確認)。そのため本ツールが集計をやり直させることはできず、前回の同期時点の値に双方の増分を足す。両方の PC で同じだけ増えていても足す。回数は整数、同席の秒数は小数を持つ実数で、要約にはその値をそのまま残す。2 台で同時に Friend Connect を動かしていた期間は両方が同じ同席を数えているので、足すと二重に数える。集計の行には時刻が無く、履歴のように稼働区間で除くことはできないので、精度より「片方の PC の分が反映されない」ことを避ける方を取った。
- 集計を規則に加える前の版のツールが取った要約には集計の祖先が無く、双方の増分が分からない。その最初のマージは中止せず、両方にある行は列ごとに大きい方の値を残し (双方の増分を足すと、共通の祖先の分が二重になる)、手元にしか無い行を足す。手元で消えた行は伝わらない。
- Friend Connect は、ワールド訪問の集計のうち更新から約 6 日過ぎた行を自分で消す (保持期間)。同期先で消え、手元で前回の同期の後に数えていない行は、他の編集されるデータと同じ 3-way の削除として消えたままにする。手元でその後も数えていた (値が変わった) 行は、他のテーブルと同じく編集が削除に勝つので、手元の値で戻る。手元でも古くなれば Friend Connect が消す。消えた行を次の訪問で 0 から作り直すと回数や秒数が前回の同期時点より減るので、減っていた側の値はそのまま増分として足す (祖先 4 回、作り直した手元 1 回、数え続けた同期先 5 回なら 4 + 1 + 1 = 6 回)。
- ユーザーの分析結果 (`UserAnalytics`: 割合やヒートマップの文字列) は足し合わせられないので、同期先の値を残し、無いユーザーの行だけ写す。Friend Connect はこの表を 2025 年 9 月以降更新していない。ユーザーやワールドの `score` (Friend Connect が集計から求める値) は対象外のままで、同期先の値が残る。

マージの前に `_prisma_migrations` の最新のマイグレーション名が本ツールの確かめた版と一致することを確かめ、違えば中止する。

Friend Connect のマージは、Friend Connect が停止している間に、その DB のコピーに対して行単位で書き込み、結果をファイルとして配置する（元のファイルはバックアップに残る）。Friend Connect のコードや通信には触れないが、Friend Connect 自身が作ったものではない行が DB に入ることになる。利用規約上の扱いを利用者が判断して有効にする前提で、既定は無効である。

## 切り替えと実行

GUI では設定カードの「VRCX をマージで同期 (試験的)」「Friend Connect をマージで同期 (試験的)」で切り替える。CLI では次のとおり（`vrcx` を `friend-connect` に替えると Friend Connect）。

```powershell
# 有効化 / 無効化
dotnet run --project src\VRCToolsDataSync.Cli -- merge vrcx --enable
dotnet run --project src\VRCToolsDataSync.Cli -- merge vrcx --disable

# 何を足すかを確かめるだけ (手元にも同期先にも書かない)
dotnet run --project src\VRCToolsDataSync.Cli -- merge vrcx --dry-run

# 今すぐマージして Push する
dotnet run --project src\VRCToolsDataSync.Cli -- merge vrcx
```
